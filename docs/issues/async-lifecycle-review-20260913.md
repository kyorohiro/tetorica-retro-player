# 2026-09-13 非同期ライフサイクルのレビュー修正

## 本体

HLSの接続待ち中に別動画へ切り替えたとき、旧onCreatedが現在の参照を上書きする問題を修正。
URLプレビューのonCreatedで要求番号を確認し、旧メディアを解放して中断する。
レンダラー準備・シェーダー待ち・音声接続・再生前の待機後にも現在の要求かを確認する。
Visual previewの接続ヘルパー自身もawait中の要求変更を検知する。
音声エンジンは初期化前後でmediaRefを確認し、古い動画の接続で現在の音声を切断しない。

WebGL初期化に世代番号を追加。destroy後に戻るコールバックは状態を更新せず、
生成完了したが表示先がなくなったパイプラインはdisposeする。
古い初期化のfinallyが新しい初期化Promiseを消さないよう、Promise自体の一致も確認する。

## Chrome拡張 Capture Tab

キャプチャー開始要求を直列化し、最新世代だけ採用する。
古い要求が遅れて取得したMediaStreamは全trackを停止する。
開始・play・音声接続中の世代変更にも対応し、pagehideで停止する。
古い要求のエラーを新しい要求の失敗として表示しない。

stopCaptureは音声終了Promiseを返し、次の開始は終了完了を待つ。
音声終了処理は対象のsource/engine/contextを最初にローカルへ退避して共有参照を外す。
終了待ち中に新しいリソースができても、それをnullにしたりcloseしたりしない。

## 検証

- 型チェック通過。
- 本体81テスト通過。実際のpreviewUrl関数を使い、古いHLS onCreatedが
  現在の動画参照を書き換えず旧メディアを解放することを確認。
- 拡張24テスト通過。実際のviewer関数を使い、旧キャプチャーの破棄、
  取得待ち中の停止、旧音声終了処理から新しい接続を保護することを確認。
- 拡張JSチェック通過。

実機では動画の連続切り替え、初期化中のプレビュー開閉、Capture Tabの切り替えを確認する。
既存のFFmpeg起動直後の現象と今回の競合が同一原因かは、まだ確定していない。
