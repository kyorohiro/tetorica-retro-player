# 拡張での改善を本体へ反映（2026-09-12）

Windows Chrome の拡張について、ユーザーから「フリーズがなくなった」「本体より安定している感じ」と確認を得た。本体にもコンパイル中の GPU 操作を抑える対策を追加した。これは `recover02-main.md` の修正に続く変更。

## 変更

- `KHR_parallel_shader_compile` が利用できる場合、完了を最大15秒待つ。従来は900ms経過すると未完了でも `LINK_STATUS` を同期取得していた。今回は未完了のまま同期取得せず、タイムアウトとして停止する。
- メインと補助シェーダーのコンパイル中は、描画・動画テクスチャのアップロード・ピクセル読み戻しを止める。準備中のキャプチャ要求はエラーを返す。
- canvas の描画バッファのリサイズは最後の要求を保持し、準備完了後の描画で反映する。キャッシュ済みフィルターへの切り替えも、進行中のコンパイルを待つ。
- タイムアウトしたパイプラインへの追加描画・コンパイルを止め、画面に再読み込みの案内を出す。タイムアウト後は明示的な GL 削除呼び出しも避け、コンテキストの回収に任せる。
- 通常のコンパイル失敗でも、同じバリアントの要求を毎フレーム再試行しない。別バリアントへ変更した後は再試行可能。
- 初期化タイマーが古いフィルター設定で現在の選択を上書きしないようにし、初期コンパイル完了時も現在の選択と一致する場合だけ適用する。

## 検証

- `npm test`: 30件通過。今回追加した3件は、900msを超える完了待ち、15秒タイムアウト、補助シェーダー準備中の描画停止をモックで検証する。リサイズ要求の集約と、タイムアウト後に同期取得・追加コンパイルを行わないことも確認。
- `npx tsc --noEmit`: 通過。
- `npx vite build`: 成功。チャンクサイズの警告あり。

## Windows での確認

本体の Windows GPU 上での動作は未確認。起動、動画再生中のプリセット連続変更、wide glow 切り替え、準備中のウィンドウサイズ変更を確認する。準備中は映像の更新を一時停止し、完了後に最新の設定・サイズで再開する設計。

KHR 拡張がない環境では短く待機した後に同期確認する経路が残る。また、同期 WebGL 呼び出し自体を JavaScript から中断する対策ではないため、すべてのドライバー停止を防ぐ保証はない。タイムアウトした場合はプレイヤーを再読み込みする。

拡張のコードと配布 ZIP は変更していない。
