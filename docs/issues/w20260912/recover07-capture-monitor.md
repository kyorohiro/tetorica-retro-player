# 画面共有のモニター音と録音を分離

画面共有開始時に本体の音が重なって聞こえるという報告への対応。通常の動画・音声再生のミュート動作とは分ける。

- 本体の画面共有開始時と、外部から渡された画面共有ストリームの読み込み時に、本体のスピーカーを初期ミュートにする。音を聞きたい場合はユーザーが解除できる。
- 共有前のミュート状態を保存し、共有の後片付けで復元する。
- 画面共有のWebAudio経路に限り、再生用monitorGainと録音用出力を分離する。ミュート・音量0はmonitorGainにだけ作用し、FXや生成ノイズを含む録音信号を止めない。Native / FX OFFの元ストリーム直接録音は従来の修正を維持する。
- 通常再生は従来どおりmasterGainに音量・ミュートを適用する。
- 画面共有かどうかはdisplaySurface、または本体のgetDisplayMedia取得時に付けたWeakSetの印で判定する。単にpreviewKind=captureやMediaStreamであるだけでは適用しない。カメラ・マイク・通常ファイルを除外する。
- monitorGainは初期値0で作り、配線中の一瞬の音漏れを避ける。

検証: `npm test` 44件、`npx tsc --noEmit` 通過。`npx vite build` 成功（チャンクサイズ警告あり）。追加テストで共有時の録音ゲイン維持、ミュートと音量0、通常再生への復帰、共有とカメラ・マイクの区別を確認した。

Windows実機の二重再生解消・録画ファイルの音声は未確認。画面共有を取り直し、開始時にスピーカーがミュート表示になること、FX ON/OFFそれぞれの録画に音声が残ること、通常動画に戻すと共有前のミュート状態へ戻ることを確認する。共有ダイアログ側の音声共有はONにする必要がある。
