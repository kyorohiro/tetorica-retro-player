# 本体のキャプチャー録画音声

`npm run dev` の本体で、ウィンドウをキャプチャーして録画すると Audio FX の生成ノイズだけ保存されるとの報告。ユーザーは二重再生を避けるためキャプチャー中の音声をOFFにしている。OFFにしている操作と、共有ストリームに音声トラックがあるかは確認中。

## コード上で確認した問題と修正

1. ネイティブ再生でWebAudioを迂回するストリームでも、録画のフォールバック候補にエフェクト回路の録画先が含まれていた。この回路に元音声が入力されていなければ、生成ノイズだけを拾い得る。該当経路は元のライブストリームを最優先し、エフェクト回路の録画先を候補から外した。WebAudio経由の場合は従来どおり処理済み音声を優先する。
2. 音声グラフの初期化が同時に要求されると複数グラフを作り得た。入力を接続したグラフと後から参照する録画先が一致しなくなる競合を防ぐため、進行中の初期化Promiseを共有する。失敗後の再試行は可能。
3. ライブ音声は録画専用にcloneし、録画停止時にそのcloneだけを解放する。
4. 録画開始時のデバッグログに経路、候補ごとの音声トラック数、選択優先順位を追加。

## 検証

- `npm test`: 39件通過。今回追加した4件は初期化共有、失敗後再試行、ネイティブストリーム録画の優先順位、WebAudio経由の優先順位。
- `npx tsc --noEmit`: 通過。
- `npx vite build`: 成功（チャンクサイズ警告あり）。

実ブラウザーで報告症状を再現・解消した確認ではない。共有元が音声トラックを提供しない場合、生成ノイズ以外の音はアプリ側では復元できない。本体ミュートも現在は録音元のmaster gainに作用するため、OFF操作が本体ミュートなら、モニター音声と録音レベルの分離を別途行う必要がある。

拡張は変更していない。
