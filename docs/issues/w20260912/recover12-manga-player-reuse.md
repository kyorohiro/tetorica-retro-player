# 漫画ページ送り時のRetroPlayer再利用

初期レイアウトの不整合を修正し、ユーザー確認で症状が解消した後の独立した最適化。

Retro表示の画像ページ（通常画像・HEIC）では、PreviewPageと内部RetroPlayerのReact keyをページに依存しないものにする。
ページ送りではsrcを更新し、描画パイプラインとそのシェーダープログラムキャッシュを維持する。
Retro/Native、forcedKind、HLS設定の変更や動画・音声等への切り替えでは従来の再生成を維持する。

- 次ページの取得中は旧画像のsrcと表示名を一緒に維持し、旧srcを新しい名前で再読み込みさせない。
- 遅れて完了した旧要求は新しいページを上書きしない。
- 要求取消・ダイアログ終了後に取得できたBlob URLも解放する。
- 取得失敗時は既存のエラー表示を使用し、その次のページで復帰できる。
- 600msの準備表示遅延やコンパイル待機処理の変更は含めない。

テストではReactの実際のマウント回数（RetroPlayer本体はスタブ）で再利用を確認。連続ページ送り、遅延結果、終了時の解放、エラー復帰、モード別キーも検証する。
実ブラウザーのWebGLでの見た目・性能は別途確認が必要。
