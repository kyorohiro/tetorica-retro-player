# 本体の継続再生負荷を削減

古い Windows 機で断続的な停止・音切れがあるとの報告を受け、本体から改善した。実機の原因は未確定であり、今回はコード上で確認できた不要な処理を削減する。

## 音声

- ビットクラッシャーの mix=0 は入力を直接コピーする。サンプルごとの乱数生成・量子化を省く。入力がないチャンネルはゼロにする。
- k-rate のパラメータ読み取り、ビット深度・ホールド長・量子化係数の計算をサンプルループの外へ移す。
- ノイズ用の別ビットクラッシャーも、ノイズ量が0のとき mix=0 にする。従来は出力ゲインが0でも mix=1 の計算が残っていた。
- バイパス中は保持サンプルと誤差をリセットする。有効に戻す際は新しい入力から処理するため、その瞬間の内部状態は従来と異なる。

有効時の48設定（ビット深度4種、ホールド長4種、mix3種）について、固定乱数列で8ブロックずつステレオ処理し、変更前の HEAD と Float32 出力が完全一致することを確認した。無効時のコピー・欠落入力・有効時の量子化・再有効化は4件の回帰テストにした。

## 描画

`useRetroPixiStage` は毎フレーム設定を複製していた。一方パイプラインは設定オブジェクトの同一性で VBlank の前フレーム再利用を判定するため、その経路で再利用が妨げられていた。

React から受け取った設定を変更せずに渡し、同じ設定のフレームでは同一性を維持する。VBlank が有効な場合の描画・アップロード省略と、設定変更・バッファサイズ変更時の再描画をテストした。VBlank が無効な場合の描画頻度は変わらない。

## 検証と次の確認

- `npm test`: 35件通過。
- `npx tsc --noEmit`: 通過。
- `npx vite build`: 成功（チャンクサイズ警告あり）。

Windows 実機での改善率や音切れ解消は未確認。同じ動画で音声FX無効・有効、VBlank無効・mild・strongを比較する。音色変更直後のノイズやクリックも確認する。

拡張のコードと ZIP は更新していない。拡張の内部描画解像度調整は別の作業として残る。
