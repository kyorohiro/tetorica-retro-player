# プレビュー再生成時のシェーダー準備表示

## 原因

プレビューを開くたびに新しい描画パイプラインを生成する。アプリ内のプログラムキャッシュはパイプライン単位なので、新しいインスタンスの準備を省略できない。
起動処理、コンパイル状態通知、プレイヤーの状態監視が直接DOMの準備表示を要求し、さらにReactのプレビュー側にも即時表示の経路があった。

## 変更

- 直接DOMの準備表示は、最初の要求から600ms経過した場合に表示する。
- Compile/Linkなどのラベル更新でタイマーをリセットしない。
- 完了・アンマウント時は表示予約を取り消す。
- エラー表示は即時表示できる経路を維持。
- Reactの全画面準備表示とプリセット変更中の表示にも600msの猶予を設ける。
- 画像のページ送り表示は従来の挙動を維持し、シェーダー準備表示のみ猶予を適用。
- キャッシュ命中を仮定してコンパイルや完了待ちを省略しない。Windows/ANGLE対策の待機・描画停止は維持。

キャッシュの有無ではなく実際の待ち時間で表示を決めるため、初回でも短ければ表示せず、再表示でも600msを超えれば表示する。

## 検証

タイマーによる短時間処理の非表示、段階更新中の表示、完了時の予約取消、即時エラー、React側の終了・再マウントをテスト。
実機でプレビューを閉じて再度開いた時の見た目は別途確認する。
