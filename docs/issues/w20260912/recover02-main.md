# 本体のコンパイル管理修正（2026-09-12）

Windows Chrome の拡張確認と並行し、本体 `src/retro-player/video/TetoricaRetroVideoPipeline.ts` を調査した。本体で既に改善している描画構成を基準とし、ローカルで再現できる待機・破棄・リソース管理の不具合を修正した。

## 見つかった問題と修正

1. **順番待ちの枠が解放されない。** コンパイル待ちの後にキャッシュが見つかった場合の `return`、および破棄済みの場合の例外が `try/finally` の外にあった。これらも解放処理を通るようにし、後続のコンパイルが永久待機しないようにした。
2. **開始準備の失敗が進行中キャッシュに残る。** 状態表示・描画待ち・シェーダー割り当てまでを後片付けの対象に含めた。リンク前に失敗した場合のシェーダーも解放する。
3. **破棄後にプログラムが登録される。** 状態表示待ち、GPU 完了待ち、プログラム登録の前後で破棄とコンテキスト喪失を確認する。遅れて戻った結果でキャッシュや補助プログラムを復活させない。破棄済みの初期化タイマーや描画呼び出しも止める。
4. **補助プログラムが重複作成される。** 同時に要求された場合、待機前のキャッシュ確認だけでは両方がコンパイルしていた。待機後にも確認し、先行処理の結果を使う。対象は縮小・曲率・wide glow の6種類。
5. **頂点バッファが未解放。** 所有するバッファを保存し、`dispose()` で解放する。二度目の `dispose()` は処理しない。
6. **非表示の診断が通常再生にも残る。** 最初の200フレームで行っていた `gl.getError()` と診断文字列作成を、デバッグ有効時だけに限定した。開発モードでは従来どおり有効。

## 検証

- 新規テストのうち、待機・破棄・重複作成・解放に関する7件は修正前に失敗することを確認した。
- 通常再生の診断読み戻しを行わないテストを追加し、新規8件が通過。
- `npm test`: 既存19件と合わせて27件通過。
- `npx tsc --noEmit`: 通過。
- `npx vite build`: 成功（大きなチャンクに関する警告あり）。

テストは WebGL をモック化したライフサイクルの検証。Windows GPU 上でのフリーズ解消や描画速度を測定したものではない。

## 今回変更していない点と次の確認

- 本体のシェーダー構成と、GPU 完了待ちの900ms上限は変更していない。上限を過ぎると `LINK_STATUS` を同期取得するため、ここが実機で停止するかは引き続き確認する。
- 同期 WebGL 呼び出し自体を JavaScript から中断できるようにする変更ではない。
- 初期フィルターのコンパイルと設定変更が重なる場合の選択結果、画面の見た目、実際のコンテキスト喪失からの復旧は追加の実機確認候補。
- 本体では、起動直後の停止、動画切り替え、プリセットの連続切り替え、wide glow の連続切り替えで、待機が残らず再生を続けられるかを確認する。

拡張側のファイルと動作確認用 ZIP は、この修正では更新していない。Windows で確認中の拡張と、本体の修正を別々に評価できる。
