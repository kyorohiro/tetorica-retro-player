# Tauri起動直後のFFmpegプレビュー

ユーザー報告：Tauri起動直後、FFmpegモードの初回だけ読み込み表示が出ず、
音声が進む一方で映像が止まる。実機での根本原因は未確定。

コード上では、playイベントによるpaused=falseだけでも読み込み表示を終了し、
シェーダー準備完了後のレイアウト・auto target待ちを再生開始条件に含めていなかった。
また、HLS開始確認がmedia.src内の.m3u8だけを検査し、hls.jsのblob URLでは省略された。

対応：
- 読み込み終了とHLS開始確認では、videoに現在フレームと有効な動画寸法があることも要求する。
- HLSインスタンス・保存されたmanifest URLでもHLSを判定する。
- URL経由のHLSをCanvasへ表示する場合、初回の描画処理を通るまで自動再生を待つ。
  シェーダー準備後、Loading video preview...を表示して最大8秒待つ。
  ソース切り替えで待機終了、タイムアウトは既存のエラー表示へ進む。
- playingイベントで状態を再同期する。破棄済みvideoのresizeは無視する。

描画確認はCPU側で描画処理を通ったことを示す。GPU完了の同期問い合わせや
readPixelsは追加しない。ネイティブ動画面・音声のみの再生にCanvas待ちは追加しない。

型チェック・80テスト通過。Tauriを完全終了して再起動し、初回FFmpeg動画を開いて
読み込み表示から映像・音声へ移行するか実機確認が必要。
